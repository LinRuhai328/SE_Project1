# 实验一多轮审查意见（待李睿豪人工核对）

审查时间：2026-10-16T16:26:09+08:00  
对象：10-16 版工作稿的三个文件。原始报告为六页，后续补入课程说明的工作稿单独更新。  
性质：AI 按学生审稿视角做的辅助评审，不代表李睿豪已经人工批准，也不构成雷业成的新业务答复。这里只审文档，不宣称已经测试不存在的软件原型。

## 先看结论

当前适合作为继续澄清的工作稿，尚不能当最终提交版。最重要的不是再增加需求，而是把角色、状态、结算与统计口径说定，并留下真实的补充沟通和本人审查依据。

现稿有30条、十字段齐全，按状态标签计17条已确认。但至少6条已确认项的验收仍依赖未决选择。课程可以提供必须有某能力的依据，不能自动确认该能力尚未定义的具体处理结果；因此不以17这一标签计数作最终数量达标结论。

## 四轮怎样查

1. **任务与来源轮：**检查三文件、十字段、唯一ID、课程最低范围、27段原话、甲乙方归属、真实补充沟通与标签。
2. **业务反例轮：**用代记、同额消费、混合截图、失败重试、旧页审核、结算后更正及个人账本自审等例子，检查是否能给出唯一验收结果。
3. **交付一致轮：**核对初稿嵌入和哈希、Git标签、报告与需求口径、两种PDF名称、当前交付副本及个人仓库引用。
4. **反向复核轮：**排除下文列出的误报，保留有明确条目或原文依据的问题；不为凑轮数或问题数重复制造缺陷。

优先级为本次评审建议：P0表示最终提交前必须收口，P1表示会影响范围、实现或验收。它们不是学校公布的扣分等级。

## 已通过或排除的误报

- 30个REQ编号唯一，十字段顺序正确，关联需求指向有效ID；没有因为少于某个任意“50条”数目就判不足。
- 27段原始发言增加编号后仍可逐字还原；首个AI完整输出在chat、来源快照和lab1-ai-draft中一致，标签没有移动。
- 课程明确可以作为需求来源，所以不能一概认为“不是甲方口述就不能确认”。问题在于是否把课程没有规定的细节也当成已确认。
- 截图、AI、真实资金和第三类角色已经标明待确认，不应再把这些候选方案误判为“已伪造甲方承诺”。
- 正确内容允许保留，不要求至少造出三个AI错误；当前辅助记录没有伪装成本人已经审查。不过真实本人判断仍要补。
- 任务书明确允许初稿后追加补充沟通，不能为了新口头顺序说明重建历史或移动标签。需要完成的是实际回访。
- 指定模板是写作框架，没有看到必须两页的要求，报告六页或七页本身不是缺陷。
- report.pdf与request.pdf当前是同内容别名；真正的风险是最终只能选择课程要求的一个名称，不能直接断言其中一个必定错误。
