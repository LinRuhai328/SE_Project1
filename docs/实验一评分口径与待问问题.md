# 实验一评分口径与待问问题

**能确定的是评分关注点，现有录音没有给出完整分值表或逐项扣分数。** 下面区分任务书硬性要求、现场可辨答复和阅读建议，不把建议当成额外规则。

## 最值得把精力放在哪里

| 关注点 | 能确定的口径 | 依据 |

## 硬性要求另按书面任务核对

- 至少一轮正式访谈和一轮补充沟通，保留真实时间、原话及来源编号；每人提交本人作为工程师的成果。
- 至少15条已确认需求，其中功能至少10条、非功能至少3条；15不等于10加3。每条已确认需求应有可观察可判断的验收，至少5条写明异常、边界或冲突。
- 选定项目的“至少覆盖”范围和共同深度要求都要体现，包括三类不同权限角色、四个有效状态、多条件查询及至少一种统计／汇总、至少两类重复／并发／超时／状态冲突场景，以及持久化、一致性和审计。
- 保留完整AI实际输入、首次完整输出及后续过程，至少3个代表性审查结果。不能为了制造修改诱导错误或编造沟通。
- 原路径需求文件、两标签及版本差异可查；最终文本与lab1-final逐字节一致，仓库对课程检查者可访问。
- 最终只有三文件，按课程网站截止时间提交。录音提到10月30日，但未给出可据此写死的准确时分或迟交扣分表。

这些是任务要求。**材料没有说明漏每一项分别扣多少，不能自行编成扣分表。** 三条非功能需求也不等于必须分属三个不同类别，具体条目须目标独立、标准可测，不能重复拆分凑数。

## 最值得进一步问助教

1. **审查质量怎样分档？** “除了数量等硬性项，怎样的审查算比较充分？能否拿一个例子说明一般核对与高质量审查主要差在哪里？”现有答复说看程度，但没有给分档例子或权重。
2. **‘已确认’怎样计数？** “功能是课程规定必须有的，但具体统计口径或权限还待甲方确定，这条能计入已确认吗，还是要等验收结果也明确后再计？”这是当前记账稿最实际的口径问题。
3. **人工确认怎样留证？** “我先用AI辅助找问题，再本人核对来源、决定采纳与否，并写清理由和实际修改。这样主要还要补什么，才算体现了人工审查？”不要重复问是否允许AI辅助，录音已经回答允许。
4. **额外功能怎样考虑？** 仅在准备花时间加功能时问：“额外功能是看需求分析的深度，还是本次实际做出软件？有没有单独加分或上限？”不清楚前，优先把必做业务和审查讲清。
5. **交付口径。** 确认最终PDF用`request.pdf`还是模板的`report.pdf`；课程网站准确截止时分、迟交处理，以及私有仓库指定查阅账号和只读提交方式。它们未在当前材料中给全。

仅在两人确实选择同题时，再问“同题是否允许、是否影响分数、依据是什么”。你们当前不同题，这不是本轮必须追加的沟通。

## 读TASK注释时怎样区分

- **任务要求**：书面最低要求；不另猜扣分数。
- **评分重点（录音）**：可辨的现场答复，带A/B时间定位。
- **阅读建议**：为了把要求落实的具体做法，不是新评分项。
- **待问清楚**：转写含糊、缺少量化说明或材料口径不一致。
